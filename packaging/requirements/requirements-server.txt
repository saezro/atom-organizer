# Dependencias del pipeline SIN interfaz, para el contenedor del Cloud Run Job
# y para la Raspberry Pi (modo `--server`).
#
# No es requirements-linux.txt menos cosas al tuntún: esa lleva PySide6, shiboken,
# pyinstaller, ipykernel y jupyter, que en un contenedor que no pinta nada ni
# construye nada son ~400 MB de imagen y superficie de dependencias a mantener.
# Aquí solo está lo que el pipeline importa de verdad (atom_core, pipeline, exif,
# utils). Las transitivas (dateutil, six, fonttools…) las resuelve pip.
#
# Las versiones se mantienen clavadas a las de requirements-linux.txt: el
# contenedor debe procesar el vuelo EXACTAMENTE igual que el escritorio, y una
# numpy distinta ya es una diferencia numérica que nadie va a estar buscando.
# Esa premisa NO ha cambiado — la paridad es entre los tres entornos
# (Windows / Cloud Run / Raspberry Pi), no con las versiones de 2023.
#
# 2026-08-18 — actualización en bloque de los tres requirements. Los pines de
# 2023 no instalaban en la Pi: Raspberry Pi OS trixie trae Python 3.13, y
# matplotlib 3.8.0, numpy 1.24.2, pandas 1.5.3, Pillow 10.0.1, psutil 5.9.6 y
# pyexiv2 2.8.1 no publican wheel para cp313. pyexiv2 además NO publica NINGUNA
# wheel aarch64 hasta la 2.15.4, para ninguna versión de Python, así que en ARM
# ese pin subía sí o sí. Se subieron los tres ficheros a la vez para no romper
# la paridad.
#
# Las versiones elegidas son las más nuevas que tienen wheel para TODOS los
# destinos: cp311/win_amd64 (el .exe de Windows), cp311/x86_64 (Cloud Run) y
# cp313/aarch64 (la Pi). Por eso numpy se queda en 2.4.6 y no en 2.5.2, y
# tifffile en 2026.3.3 y no en 2026.8.16: las 2.5.x/2026.8 exigen Python >= 3.12
# y dejarían fuera al escritorio.
#
# Equivalencia de comportamiento verificada con un A/B viejo-vs-nuevo sobre los
# mismos ficheros de entrada (scratchpad `diff_run.py`): LUT térmica de los 4
# colormaps, JPEG de color gradiente, JPEG de escala de grises, TIFF float32 de
# salida, compresión con EXIF, giro 90º, XMP del gimbal + EXIF GPS por pyexiv2,
# y CSV/XLSX por pandas → sha256 IDÉNTICO en todos. Los tags de ExifRead, las
# distancias de geopy y el orden de natsort también salen idénticos. La única
# diferencia observada es de representación, no de valor: pandas 3 tipa las
# columnas de texto como `str` en vez de `object`, pero conserva `np.nan` como
# valor faltante (`StringDtype(na_value=nan)`), así que el patrón
# `str(v) == "nan"` que usan pipeline.py y atom_core/estadillo.py para detectar
# celdas vacías sigue funcionando igual — comprobado sobre el estadillo real.
# Qt NO está y no debe volver. Las fases del pipeline vivían dentro de la clase
# Qt `MainWindow`, así que importar el pipeline importaba PySide6: ~400 MB de
# imagen por una dependencia que el contenedor no usa para nada visible. Ahora
# viven en `atom_core/phases.py`, sin Qt, y de ahí las heredan tanto la GUI como
# el host headless. `tests/test_pipeline_sin_qt.py` importa `atom_core.organize`
# con PySide6 vetado: si alguien reintroduce el acoplamiento, CI lo para antes
# de que la imagen vuelva a engordar.
